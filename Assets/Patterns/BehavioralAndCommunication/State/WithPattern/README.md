# State: with the pattern

The same feature built with State. The idea, from the page: Model the object as being in exactly **one state** at a time. Each state is an object that handles input and updates for that mode, and decides when to **transition** to another state.

Compare it with [WithoutPattern](../WithoutPattern/README.md): the behaviour that broke there should hold here, at the cost of the extra types the pattern adds.
