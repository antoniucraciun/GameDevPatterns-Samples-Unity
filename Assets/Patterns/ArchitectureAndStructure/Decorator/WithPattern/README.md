# Decorator: with the pattern

The same feature built with Decorator. The idea, from the page: Give the object and its add-ons **the same interface**. Each add-on, a **decorator**, **wraps** another object implementing that interface, forwards calls to it, and adds its own behaviour before or after.

Compare it with [WithoutPattern](../WithoutPattern/README.md): the behaviour that broke there should hold here, at the cost of the extra types the pattern adds.
