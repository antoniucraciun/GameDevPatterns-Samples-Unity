# Interest Management

**Category:** Networking & Multiplayer · **Site slug:** `interest-management`

> Only replicate entities that are relevant to each client.

## What this sample will show

WithoutPattern builds a small feature the straightforward way and runs into the problem the page describes. WithPattern builds the same feature with Interest Management, so you can run both and compare them.

The problem, from the page:

> A battle royale has 100 players and 5,000 networked objects (loot, doors, vehicles, projectiles). Sending every object's state to every client means 100 × 5,000 updates per snapshot: bandwidth explodes, server CPU is spent serialising things nobody can see, and clients waste memory and time on entities on the other side of the map.
